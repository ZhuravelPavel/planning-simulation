# How search works

Search is one way a property gets an audience. It is not a separate department, and it is not a plan for one site. Pavel is the Ads, Marketing, and SEO lead, so search sits in that role on every property. Simon, the development lead, makes the page match what Pavel assigns, on any site. There is no separate search team.

Not every property uses search the same way. On a property whose visitors come from Google, search is how the advertising audience arrives. On a property people already know, most visits are direct, and search is only the public part of the site. On a product that is sold on its own, the pages must be describable without the other properties, and rankings are not how the first users arrive. A new project follows whichever of those it actually is. Pavel decides that. Rotchilda, the project manager, tracks the work when the change also needs Simon or has to be reported onward. She does not assign queries or write titles.

## How a query becomes a page

A query is assigned to one indexable URL. Internal links point at that URL and not at a second page competing for the same words. Pavel makes the assignment. Simon places it in the theme when the link is part of the template.

Two addresses for the same query split it. That includes a second path on the same site, a subdomain ranking beside the main host, and a sitelink that search treats as the result. One address is the result. The other may be a sitelink. Both are not the result.

The page and the home of the property do different jobs. The page is the thing the query names. The home is the brand and the directory. If the home also tries to rank for the query, the query lands on the address that does the job worse.

A blog post can support a page by linking into it. The blog is not the object that carries the property’s search traffic. A new URL is justified only when the intent is not already a page, and not already assigned. Pavel makes that call. A keyword list is a map of language. It is not a list of pages the site is obliged to open.

Where a property is in more than one language, a language is one page for one query, not a translation of the whole site, and only once the main language’s queries each have an address.

## How a page is put together

The parts are the same on any property.

The URL is the one address for that query. A second path for the same wording splits the query.

The title and the description use the wording people search, and they say what the page is. The heading and the opening say the same thing. A page that contradicts itself, for example by describing a price on a product that does not charge, is the wrong page.

The body covers the query. Links go to the real destination, not to a placeholder. Existing links keep working. Where the page has a repeating structure, such as questions and answers, that structure can be marked so search can read it. Images have a description. The page is readable on a phone.

Pavel is responsible for the words. Simon is responsible for them being what the site serves.

After publication, the address is submitted and included in the sitemap. Impressions and the set of queries move first. Position and the rate at which people click move later. The page is not judged on the first days of clicks.

A page that is the product and a page that recommends other companies’ products are different objects. They do not share one URL. A recommendation page says what the other product is, what it costs, what it is good and bad at, and that the link is paid. The disclosure is part of the page. Pavel owns that page. Simon owns the path.

## How search is read

Three tools answer three questions. They are not three copies of the same number.

| Tool | What it tells you |
| --- | --- |
| Search Console | Clicks, impressions, how often people click, and average position, by query, page, country, and device |
| A rank tool | Which URL it thinks ranks for a keyword |
| GA4 | Sessions by channel, and whether a session became a use of the product, once that use is defined |

Search Console is the click count. The rank tool is the URL assignment. They disagree often enough that an assignment with almost no clicks is a sitelink, not the ranking page. Pavel reads both. GA4 is useful for search only when a visit can be tied to someone actually using the property. Pavel sets up that event tracking and the other metrics. Simon helps him. Until it exists, a better ranking cannot be read as more use.

Links from the property’s own pages, and from pages that already have authority, are how a new URL acquires strength. Buying links is not the mechanism.

The volunteers who moderate a chat community are not responsible for search, titles, or rankings.
